# おもいでクローゼット 1.3.0

小さくなった子供服や、大切なアクセサリー・おもちゃを、写真と思い出の記録で残す個人用Androidアプリです。

## 更新と最初の使い方

1. `omoide-closet-1.3.0.apk` をAndroid端末で開いてインストールします。Android 8.0以降が対象です。1.0.0・1.1.0・1.2.0と同じパッケージ・署名鍵で、versionCodeを4に増やしています。前のアプリをアンインストールせず、上書きで更新すると写真と記録を引き継ぎます。
2. ホームはユーザーの手描き案に合わせた3つの表示です。上段はトップス（ワンピースやつなぎを含む）が左から右、下段はボトムスが右から左へ流れます。上下を独立してスワイプ・一時停止・再生・送り戻しできます。
3. 下の小さな棚では、アクセサリー・おもちゃ・その他の品が12秒ごとにクロスフェードします。タップで思い出を開き、↻で次の品を表示します。
4. 写真がない間は明記したサンプルを展示します。右下のカメラボタンから撮影・写真選択ができます。1点目の登録後は、ご自身の写真に切り替わります。
5. 背景除去と分類の結果を確認し、名前・大きな分類・種類・誰の宝物・サイズ・時期・思い出を直して「クローゼットに残す」を押します。上下の振り分けも編集できます。服以外の品はハンガーに掛けず、棚に置く表示です。
6. 下のメニューは「ホーム・検索・設定」です。検索では写真の一覧、名前・思い出・種類での検索、編集、お気に入りが使えます。ホームはお子さんごと・お気に入りで絞れます。
7. AI分類を使う場合は設定でご自身のGemini APIキーを貼り付け、写真の送信を有効にして「設定を保存」します。

家族用のSQLiteテーブルを追加し、既存の服の記録を維持して移行します。以前の呼び名は家族プロフィールに引き継ぎ、以前のZIPバックアップにも対応しています。

## 1.3.0で追加した思い出の残し方

- 設定の「家族の顔と呼び名」で、名前の変更・家族の追加・任意の顔写真登録ができます。顔写真を撮る／選ぶと、指で位置を動かし拡大して丸い表示に合わせられます。顔を認識して人物を自動判定する機能ではなく、登録した顔をタップして選ぶ方式です。
- 取り込み前と編集画面で、家族の顔を複数選べます。お下がりなど、同じ服を姉妹・兄弟が使った記録は、どちらの家族のフィルターからも見られます。名前を変えても、固定の家族IDで紐付けを維持します。
- パジャマの上下は別々に撮影・登録し、上を「トップス」、下を「ボトムス」に指定します。「セット・関連アイテム」で相手を選ぶと双方の記録が紐付きます。詳細画面から関連アイテムを開けます。どちらから解除しても双方から外れます。
- 「裏面の写真」は任意です。表だけでも保存できます。裏面を追加すると背景を切り抜き、手動補正も使えます。ホームのハンガーを縦にスワイプすると裏返り、横にスワイプするとその段の服が流れます。詳細画面では縦スワイプと「表／裏」ボタンが使えます。
- 着ていた姿や一緒に遊んだ日の写真を1点につき50枚まで添え、写真ごとの説明を書けます。写真をタップして拡大し、説明文も検索できます。着用写真と顔写真はAI分類に送りません。
- 裏面・関連写真の追加や取り外しはその時点で端末に保存します。名前・所有者・説明文・セットの変更は「クローゼットに残す」で確定します。外した写真は変更履歴のため、ファイルがすぐに消えるわけではありません。


## スクリーンセーバーとウィジェット

設定の「日常に、思い出を飾る」で、表示対象（すべて／お気に入り）、スクリーンセーバーの切替間隔（10～120秒）、ウィジェットの間隔（30～120秒）を選び「表示設定を保存」します。

### Androidスクリーンセーバー（Daydream）

「Androidのスクリーンセーバー設定を開く」を押し、「おもいでクローゼット」を選びます。充電中やドック接続中などの起動条件は端末の設定に従います。対応や設定画面の有無はメーカーによって異なります。「スクリーンセーバーを試す」はアプリ内のプレビューを開き、タップで戻ります。

保存した写真を暗めのクローゼットに表示し、ゆっくり左へ移動しながらフェードで切り替えます。表示位置と文字も少しずつ動きます。停止時には描画ループと写真の保持を解除します。

### ホーム画面ウィジェット

「ホーム画面にウィジェットを追加」を押して、Androidの追加操作を完了します。追加要求に対応しないホームアプリでは、ホームを長押しして「ウィジェット」から選びます。サイズの変更に対応しています。

ウィジェットは、ランダムに選んだ最大3枚の保存写真を指定間隔で切り替えます。↻で並びを選び直し、写真のタップでアプリを開きます。常時流れるハンガーの表示はアプリのホーム画面で楽しめます。ウィジェットの写真セットは約30分ごとと、登録・編集・ごみ箱・設定変更時に更新します。非表示時のアニメーションはホームアプリ側で停止されます。

どちらも保存済みの切り抜き写真だけを使い、表示中にAI通信はしません。ごみ箱の品物とサンプルは表示しません。お気に入り限定で該当する写真がない場合は登録案内を表示します。

## AI処理

- **背景除去**：Google ML Kit Subject Segmentation。生成による描き直しではなく、撮影写真の画素を切り抜きます。処理は端末内で行います。Google Play開発者サービスが必要で、初回はインターネット接続によるモデルのダウンロードを待つ場合があります。
- **品物の分類**：Gemini Interactions APIを使い、グループ・種類・上下の位置・短い名前・色をJSONで受け取ります。標準モデルは`gemini-3.5-flash-lite`。設定画面で利用できるモデルに変更できます。
- Geminiには分類対象の写真を送ります。家族の顔写真、着用写真、お子さんの呼び名、サイズ、着用時期、思い出のメモは送信しません。裏面は背景除去だけを行い、Geminiには送りません。APIの`store=false`を指定しています。サービスによる取り扱いはご自身のGemini API利用条件に従います。
- キーはAndroidKeyStoreのAES-GCMで暗号化し、端末内に保存します。このソースやAPKに実際のAPIキーを埋め込んでいません。バックアップZIPにもキーは含めません。
- APIキー未設定・通信失敗・背景除去モデルの準備失敗でも、写真を残して手動で分類・補正・登録できます。人物・サイズ・着用時期はAIに推測させません。

無地で品物と違う色の背景に1点を置き、明るい場所で端まで撮影すると、切り抜きしやすくなります。人物が服を着ている写真より、服だけの写真が適しています。

### 切り抜きを補正する

「切り抜きを補正」を開いて、背景を「消す」でなぞります。服が欠けた場合は「戻す」で元写真の画素を戻せます。筆の太さ、拡大、移動、8操作までの取り消しに対応しています。「元写真から」は切り抜き全体を元の写真へ戻します。保存すると、透明な余白を整えてクローゼット表示用画像を作ります。

## Google Drive同期

同梱の `google-drive-setup.html` にGoogle Cloudの初回登録手順を記載しています。Drive APIの有効化、外部テストアプリとテストユーザー、Android OAuthクライアント（パッケージ名と配布署名SHA-1）の登録が必要です。このAPK用のCloud登録・実際のGoogleログインとDrive通信は未検証です。

同期するすべての端末を1.3.0以降へ更新してください。追加写真と家族に対応した同期形式は以前のアプリでは読めません。設定でGoogleに接続し、最初の端末で同期フォルダを作ります。ほかの端末は同じフォルダURLを入力して「このフォルダを使って統合」を押します。別のGoogleアカウントを使う家族には、Driveでフォルダを編集者として共有します。

- 表・裏・着用写真・家族の顔写真、家族プロフィール、複数所有者、セットの紐付け、名前・種類・思い出などの記録、お気に入り、ごみ箱への移動・復元を統合します。APIキー、下書き、Googleアクセストークンは同期しません。
- 自動同期はアプリを開いた時・記録した時・表示中の約5分ごとです。閉じている間の常時同期は実装していません。手動の「今すぐ同期・統合」もあります。
- 同じIDの同時編集は端末の時刻で上書きせず、変更履歴のつながりで判断します。内容が異なる場合は「同時編集の別版」として両方残します。再同期しても同じ別版を増やしません。
- 元写真・表示用・全画面切り抜きは内容のSHA-256で識別し、変更履歴はUUIDで識別したファイルとして保存します。旧版を上書き・削除しない方式です。転送・画像の内容確認が済んでから、端末の記録を更新します。通信エラー時は端末に保存した変更を残して再試行できます。
- 以前のZIPを複製した端末は同じIDを共有するため、同期時に統合できます。それぞれで新しく撮影・登録した品物は別のIDで残します。
- 既存・共有フォルダをURLで指定できるよう、この版は `https://www.googleapis.com/auth/drive` を要求します。Googleの許可はDrive全体への権限です。アプリの同期処理は指定したフォルダの同期ファイルのみを読み書きし、接続メールアドレスはDriveのアカウント情報で確認します。個人・家族のテスト利用を想定した版です。

## データとバックアップ

- 写真と記録はアプリの専用領域に保存します。SQLデータベース(SQLite)とJPEG/透過PNGを使います。写真アプリへ自動で追加しません。
- 保存画像は縦横の長い方を最大1280pxに揃えています。撮影・選択した写真の撮影方向を補正し、背景を含む画像と、切り抜きの全画面画像、余白を除いた表示画像を保存します。元のカメラファイルをそのまま保存する形式ではありません。
- 下書きはAI処理前に端末へ保存します。アプリを開き直した場合、下書きを続けられます。入力したメモ等は「クローゼットに残す」まで確定しません。
- 「アルバムから外す」はごみ箱に移します。設定から元に戻せます。ごみ箱の品物もバックアップに含めます。
- 設定の「すべての思い出をバックアップ」からZIPを保存します。Androidのファイル保存画面でGoogle Drive等を保存先に選べます。
- 「バックアップから追加・復元」は今ある記録を残し、同じIDで未登録の品物を追加します。登録済みIDはスキップします。入力ZIPは最大500MBです。
- ZIPには`manifest.json`、家族プロフィール、表・裏のJPEGと2種類の透過PNG、着用写真・顔写真、閲覧用の`closet.html`と説明が入ります。ごみ箱も復元用の写真・記録に含めます。復元は旧ZIPとこの版のZIPに対応します。この版のZIPをアプリへ戻す際は、1.3.0以降のアプリを使ってください。
- ZIPを展開して`closet.html`をブラウザで開くと、アプリと同じ見た目で独立スワイプ・再生停止・検索・思い出の詳細が使えます。表・裏・着用写真・家族の顔写真・CSS・JavaScriptを1つのHTMLに埋め込み、ネット接続なしで使えます。複数所有者による絞り込み、縦スワイプでの裏返し、関連アイテムの閲覧にも対応します。HTMLを渡す相手には、これらの顔写真や着用写真も見えることを確認してください。
- HTMLは書き出した時点の閲覧用です。編集・撮影・同期はAndroidアプリで行います。ごみ箱の品物はHTMLに表示しません。GoogleアカウントやAPIキーもHTMLに含めません。Driveプレビュー等で開けない場合はダウンロードしてブラウザで開きます。
- アプリをアンインストールする場合・端末を変える場合は、先にバックアップを作ってください。

## ビルド

JDK 17、Android SDK Platform 35、Android Gradle Plugin 8.7.3、Gradle 8.10.2を使用します。

1. Android Studioでこのフォルダを開き、SDKの場所を設定します（`local.properties`は手元の環境に合わせて生成）。
2. `./gradlew assembleRelease`、Windowsは`gradlew.bat assembleRelease`を実行します。
3. 署名を未設定の場合、`app/build/outputs/apk/release/app-release-unsigned.apk`が生成されます。インストールするAPKは、Android Studioの「Generate Signed Bundle / APK」からご自身の署名鍵で作成してください。

このソースZIPに配布APKの署名用秘密鍵は含めていません。ご自身の署名鍵を使う場合、`signing/omoide-closet.jks`と環境変数 `OMOIDE_STORE_PASSWORD`（必要なら`OMOIDE_KEY_ALIAS`、`OMOIDE_KEY_PASSWORD`）で署名する構成です。既存APKに上書き更新するには同じ署名鍵が必要です。別の署名でビルドしたAPKは既存の配布APKの更新としてはインストールできません。そのAPKでGoogle接続する場合は、手順書の配布用SHA-1を、ご自身の署名のSHA-1に置き換えてAndroid OAuthクライアントを登録します。

## 検証

`tests/ui-smoke.cjs`で320・390・430・800px幅の画面と、上下の逆方向アニメーション・独立スワイプと停止・小物のクロスフェード・撮影ボタンの位置・品物の分類・表示設定・登録・編集・検索・お気に入り・表示テキストのエスケープ・ごみ箱の復元・手動の消しゴム操作を検証します。画面の機能テストではネイティブ操作の代役を使い、端末テストで実際の保存を検証する構成です。

`app/src/androidTest/.../SmokeInstrumentation.java`には実際のAndroid上で、写真取り込み・透過PNG補正・余白除去・下書き保存・SQLiteの再読み込み・暗号化・ZIPバックアップ復元・不正なZIPの拒否・WebViewとの連携を確認するテストがあります。

`am instrument -w -e ambient true jp.omoide.closet.test/jp.omoide.closet.SmokeInstrumentation`で、実際のAndroidフレームワークによるウィジェットのRemoteViews展開・描画・間隔設定、スクリーンセーバーの読み込み・描画・停止、既存形式の記録とグループ・お気に入り・ごみ箱の扱いを確認します。19項目が1.3.0のAndroid 15仮想端末で成功しました。詳細はVALIDATION.mdを参照してください。

`-e sync true`では、Android上の別々のSQLiteと写真を2台分用意し、Drive通信だけを代役にして21項目を確認します。同時編集、端末間の一致、別版の重複防止、ごみ箱・復元・お気に入り、通信失敗後の再試行、写真の転送途中の中断と再開、新規端末への取得、実際に書き出したHTMLの写真埋め込み・キー除外・安全なテキスト処理が対象です。

`tests/sync-ui.cjs` はDrive接続・フォルダ指定・通信エラーと再試行・接続解除の画面操作と、Androidが書き出したHTMLをオフラインのブラウザで開く検証です。`CLOSET_NATIVE_HTML`に端末から取得したHTMLを指定します。`CLOSET_SAMPLE_HTML`を指定すると、同じ画面で8点のサンプルを見られるHTMLも作成します。

`tests/family-ui.cjs`は、顔の複数選択・AI再実行時の入力保持・裏面の追加と補正・縦スワイプ・セットからの移動・着用写真の説明・家族追加と顔写真のトリミングを確認します。`-e family true`では、Android上の旧SQLite移行、複数所有者、相互リンク、写真の画素を含むZIP復元と同期、同時編集した裏面の分離を検証します。1.3.0で29項目がAndroid 15仮想端末で成功しました。`tests/portable-family.cjs`では、実際のAndroidコードが作った追加写真付きHTMLもオフラインで検証しています。

Geminiの実際のAPIキーとGoogle Play開発者サービスが利用可能な実機ではまだAIの認識精度を検証していません。実機のホームアプリとスクリーンセーバーの起動条件も未検証です。写真や端末ごとの切り抜き結果は、保存前に確認してください。
